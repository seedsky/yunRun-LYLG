# USB 手机只读核对（2026-11-10）

预览版 4 首轮经 USB 调试查看已登录的官方 Android 应用，仅进入已有成绩与记录详情。预览版 5 后续按用户授权补测密码登录和代理链路，结果见下节。所有轮次均未开始、结束或上传任何跑步记录，未提交申诉、安装证书或改动官方 App。

## 已确认

- 官方应用版本为 3.6.6，与本地协议配置一致。
- 首页“我的成绩”在本机显示“暂无数据”；健跑历史实际位于“我的 → 运动记录 → 健跑记录”。没有据首页成绩空白判断跑步历史不存在。
- 官方详情显示合格标记、开始时间、里程、平均配速、用时和步频。用时来自 duration 秒数；配速来自 recodePace，而非将其当秒数或时速。
- 找到一条无效样本，官方详情明确说明跑步时间不在每日 06:00 至 22:00 的规定时间内。未根据这个样本推断其他无效记录的原因。
- 官方安装包的 NewRunRecordInfo 字段及 NewRunRecordInfoActivity 的展示逻辑确认：不合格原因直接来自 noQualifiedReason。它不是将 remake 的数字编码翻译成原因。本地详情现已保留并展示该字段；缺失时明确提示服务器未提供，不猜测。
- 列表显示的时间与详情开始时间可能不同；官方健跑列表读取 recordEndTime，详情开始时间读取 recordStartTime。工作台分别标注来源，缺少开始时间时不会将列表时间冒充开始时间，也不根据两时间差重算 duration。
- USB ADB 反向端口转发完成实际手机到电脑的 HTTP 请求与响应。本次不依赖共同 Wi-Fi；仅临时添加一个测试端口，结束已移除。不代表 USB 网络共享已验证，也不代表 HTTPS 抓包成功。

## 预览版 4 当时未完成的项目

- 源工程和正在使用的预览版所保存 token 均在只读请求中返回失效／401。本轮没有重新提交账号密码，避免影响手机当前会话；不能声称已完成实时服务器详情与官方页面的逐字段对照。
- 手机随后自动锁屏，未绕过锁屏或读取应用私有数据。后续界面核对需手机再次解锁。
- Super Proxy 已安装，但当前电脑 CA 的安装、应用信任、SOCKS5 转发及完整 token 捕获尚未完成实机验收。USB 调试转发仍不能省去 HTTPS 解密所需的证书匹配。
- 真实新建记录、轨迹上传、停止后的线上状态与最终成绩未测试。

截图、UI 层级和用于本地核对的官方 APK 留在开发工作区 .test-data/phone-check/，不进入发行包；文档未附个人身份、凭据或完整个人运动记录。

## 预览版 5 补测结果

- 使用本机已加密保存的账号密码，学校登录接口成功返回 token；加密保存后能查询一个可用任务及 13 条已有记录。日志仅记录成功状态，不回显账号密码或 token。
- 手机正常登录后，之前在电脑密码登录获得的 token 返回 401。这是本次观察到的服务端会话行为，不等于密码登录无法获得 token。
- 按用户建议开启手机 USB 网络共享；Windows 出现 RNDIS 网卡，手机直接访问电脑测试页成功。此项未使用 ADB reverse，与首轮调试端口转发分别验证。
- 电脑现有 mitmproxy CA 的公开证书指纹与用户提供的原证书一致。本次复用该既有环境，不新装手机 CA，不把原证书或私钥放入发行包。
- 在手机既有 Super Proxy 中新建临时 SOCKS5 测试配置，原代理配置没有改动。USB 网络共享 → SOCKS5 → HTTPS 解密 → 捕获 token → 服务器只读核实学校及学号 → 同账号保留密码 → 读取 13 条记录全链路通过。代理仅对配置的学校主机解密，其他主机走隧道。
- 捕获后电脑与手机共享同一当前 token，同时读取任务和记录成功；无效样本原因与官方页面一致，用时 989 秒与手机 00:16:29 一致。有效样本的判定、768 秒用时、6.4 分／公里及 167 步／分也与首轮官方详情一致。
- 抓包结束后已关闭手机代理、结束本机临时抓包进程、删除测试代理配置；原配置保留。临时充电常亮设置已恢复并核对原值。USB 网络共享按用户要求保持开启，未改动原 Wi-Fi 热点开关。
- 没有把个人资料接口返回的姓名、密码等整份保存；仅在内存核实 userName 和 schoolId，候选 token 独立使用 DPAPI 保护，验证失败不覆盖当前会话。

尚未进行真实跑步上传、停止后的服务端处理和最终新成绩验收，遵守用户不上传记录的限制。其他机型、校园网、普通热点及系统 Wi-Fi HTTP 代理不从本机 USB／SOCKS5 的结果推定必然可用；自行构建 EXE 仍只提供方法。
