## 自动验收范围

- Windows DPAPI 凭据保存/恢复、退出清除。
- 同种子复现、逐点配速起伏、临时预览不自动收藏。
- 参数冲突不自动改写、动态规则优先。
- 仅预览不改原文件、快照篡改与路径越界拒绝。
- 备份排除密码、选择性导入、同名保留两份。
- 登录失败不重试，失效 token 重新登录至多一次。
- 规则缺失来源明确、多任务不默认第一项。
- 子进程本地演练、快照一致性、中断不自动恢复。
- 浏览器检查亮/暗主题、生成预览、参数过期、路线库、备份、布局与独立工具。
- 发行包白名单、空白账号配置与个人数据排除。

### 真实任务数据的离线核对（2026-11-19）

在用户登录后的本机 `data/rules.json` 上（不联网、不提交）核对王城账号的两个任务：`620 大一东操场男生跑`、`622 大一西操场男生跑`。

- 两个任务都带 `points`（6 个点）和 `fence`（4 个顶点），编码是 `经度,纬度|…` 文本，本地解析正常，6 个打卡点都落在各自围栏内。
- 两个任务的围栏几乎是同一块校区范围（顶点相差几十米），不是两块互不相交的操场；切换任务主要换的是打卡点。
- 用这份真实数据分别生成 2 公里路线：331 个轨迹点，全部落在围栏内（0 个越界），命中 6 个打卡点，无校验错误。
- 浏览器用同一份数据（临时目录副本、伪造登录态、不联网）确认：任务栏显示真实任务名与「6 点 / 有围栏」，地图画出围栏与打卡点，路线在围栏内，深色主题下下拉框只有一个箭头。

据此把规则收紧：任务没有围栏时一律不允许生成；生成或导入的路线只要有点越界就停止，并报出越界点数。
