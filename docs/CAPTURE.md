# 手机抓包连接与证书说明

Super Proxy 在手机上，mitmproxy 在电脑上。前者使用本地 VPN 接口转发应用流量到电脑代理；证书用于 HTTPS 解密。系统 Wi-Fi 代理也是转发到电脑，但 Android App 可能忽略系统 HTTP 代理，不能保证替代软件转发。

主流程：手机打开 LAN 测试页 → 配置 Super Proxy → 安装当前电脑 CA → 官方 App 产生目标请求 → 候选 token 隔离加密保存 → 自动停止代理 → 用户关闭手机代理 → 后台验证账号并启用。

连接条件是手机可访问电脑显示的地址和端口。同一校园网可能存在隔离；不要求用某一种热点方式，也不假定热点主机与客户端必然互通。先检测，再排查。

| 测试方案 | 需要核对 |
|---|---|
| 同一校园网 | 网段路由、客户端隔离、Windows 当前网络的防火墙许可 |
| 电脑开启热点，手机连接 | 电脑网卡/共享支持，手机能否访问电脑地址 |
| 手机热点，电脑连接 | 热点主机到客户端的实际互通情况，依机型测试 |
| USB 共享 | 网络方向、可访问地址与路由，不能仅凭“已联网”判断互通 |
| 系统 Wi-Fi HTTP 代理 | 填面板 HTTP 端口；检查 App 是否遵循系统代理 |

不建议为排查而关闭整个防火墙；按实际网络允许本程序的对应端口。面板会列出多个 IPv4 地址，应选手机可访问的一项。

首次启动抓包时自动生成本机 CA，位于用户数据目录的 capture-ca/（便携版为顶层“用户数据”，源码模式为 data）。手机只能下载公开证书 .cer；私钥留在本机，不进入数据备份或发行包。旧证书只适用于与其匹配的原抓包环境，本版不保留用户最早提供的旧 .crt。

Android CA 安装入口随系统变化，通常为“安全/隐私 → 更多安全设置 → 加密与凭据 → 安装证书 → CA 证书”。仅安装用户 CA 不代表目标 App 一定接受，仍需实机确认。不自动修改手机安全设置、不修改 App、不处理证书锁定绕过。

预览版 5 实测：本机 USB 网络共享成功访问电脑测试页，并经 SOCKS5／既有匹配 CA 完成 HTTPS token 捕获。该结论仅针对本次机型与网络；校园网和其他热点仍先测连通性。新电脑仍须安装其自身抓包环境匹配的 CA，不附原证书。候选会话验证同一学号时保留登录密码，换号不继承；验证失败不覆盖原凭据。
